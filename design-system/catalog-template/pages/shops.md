# 店铺与订单状态设计规范

## 适用范围

适用于店铺管理卡片和订单列表中的订单状态展示。两处必须使用相同的状态语义、颜色 token 和交互反馈。

## 订单状态颜色

| 状态 | 状态值 | 背景 | 边框 | 文字 |
| --- | ---: | --- | --- | --- |
| 新订单 | `0` | `#edf5ff` | `#b7d6ff` | `#1677ff` |
| 客户确认中 | `1` | `#fff8e8` | `#f5d58a` | `#b77900` |
| 待生产 | `2` | `#ecfbf8` | `#9ddfd4` | `#087f74` |
| 生产中 | `3` | `#f5efff` | `#d3b8f5` | `#722ed1` |
| 待发货 | `4` | `#fff1eb` | `#ffc4ad` | `#d4380d` |
| 已完成 | `5` | `#f0f9eb` | `#b7df9f` | `#389e0d` |

CSS token 位于 `src/App.css` 的 `:root`，店铺状态使用 `--shop-status-*` 映射，订单标签使用 `--order-status-*` 映射。不要在页面组件内重新定义颜色。

## 店铺卡片

- 使用白色卡片、`24px` 外圆角和细边框。
- 卡片采用轻量 3D 指针倾斜，悬浮时向上抬升并增强阴影；不增加实体厚度条。
- 指标块使用浅灰背景、`16px` 圆角，保持紧凑高度；商品数和订单数可点击。
- 订单状态块使用约 `11px` 圆角，浅色背景和对应状态色文字；hover 上浮 `2-3px`，active 回落，键盘焦点显示状态色描边。
- 删除操作使用危险色 `#d4380d`，编辑和删除按钮保持圆形图标按钮。

## 订单列表

- 状态列使用浅色状态标签，不使用高饱和实心色块。
- 只有状态单元格使用对应状态色系的明确浅色背景：新订单蓝、客户确认中琥珀、待生产青绿、生产中紫、待发货橙红、已完成绿色。
- 订单行其余单元格保持普通表格背景；选中行仍使用统一的选中蓝背景，以保证选择反馈清晰。
- 标签使用约 `11px` 圆角、`1px` 状态边框、紧凑内边距和最小 `30px` 高度。
- 状态标签继承订单行的既有点击、选中和键盘交互；标签本身不依赖 hover 才能传达状态。
- 状态文字必须保持可读对比度，不能仅依赖颜色表达信息，文字仍需显示完整状态名。

## 动效与无障碍

- 交互过渡使用 `160-220ms`，hover 反馈不改变布局尺寸。
- `prefers-reduced-motion: reduce` 时取消位移、倾斜和非必要过渡。
- 所有图标按钮必须有 `aria-label`，店铺状态按钮必须包含店铺名和状态名的可访问名称。
